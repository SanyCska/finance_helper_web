# Финансовый Telegram Mini App — дизайн

Дата: 2026-08-02

## Задача

Личный инструмент для ежемесячного финансового ритуала владельца:

1. Выгрузить CSV из Дзен-мани, отправить боту — данные попадают в БД.
2. Посмотреть траты месяца, добавить недостающие вручную.
3. Увидеть сальдо месяца относительно зарплаты.
4. Посмотреть разбивку трат по категориям за месяц и динамику отдельной категории по месяцам.
5. Расписать план трат на следующий месяц и сравнить план с фактом.

Пользователь один — владелец. Многопользовательский режим не проектируется, но `user_id`
присутствует в схеме, чтобы не переделывать БД, если понадобится.

## Стек

**Бэкенд** (`finance_helper_back`): Python 3.12, FastAPI, SQLAlchemy 2.0 (sync), Alembic,
PostgreSQL 16, aiogram 3, httpx, pydantic-settings, pytest.

**Фронтенд** (`finance_helper_web`): Next.js 15 (App Router), TypeScript, Tailwind CSS v4,
TanStack Query, Vitest. Графики — собственные SVG-компоненты.

**Инфраструктура**: docker-compose (postgres + api + bot + web).

### Почему свои графики, а не Recharts

Мокапы выдержаны в модернистском стиле: нулевые радиусы, 2px линейки, `tabular-nums`,
плоские заливки, донат из `conic-gradient`. Приведение библиотечных чартов к этому виду
потребует больше кода переопределений, чем прямая отрисовка. Нужны всего три формы:
донат, горизонтальные бары, линия/столбцы по месяцам.

## Категории

Хранятся дословно из CSV. Нормализация, склейка дублей и разбиение
мультикатегорийных строк не выполняются — сознательное решение владельца.

Следствия, принятые как есть:
- `'Продукты в магазинах '` (с хвостовым пробелом) и `'Продукты в магазинах'` — разные категории.
- `'Подарок'` и `'Подарки'`, `'продажа'` и `'Продажа'` — разные категории.
- `'Транспорт, Рестики'` — одна категория с таким именем.
- Пустая категория хранится как `''`, отображается как «Без категории».

Категория `Correction` (47 строк) исключается из всех агрегатов: это технические правки
остатков счетов, а не траты. Список исключаемых имён задаётся настройкой
`EXCLUDED_CATEGORIES` (регистронезависимо, с обрезкой пробелов) и по умолчанию равен
`["Correction"]`.

Справочника категорий как таблицы нет — список получается `SELECT DISTINCT` по транзакциям.

## Валюты и курсы

Базовая валюта — USD (настройка `BASE_CURRENCY`). В дампе 14 валют: RSD, ARS, RUB, EUR,
USDT, JPY, PEN, BRL, AED, TRY, HUF, BAM, USD, CNY.

Источник курсов: графики Yahoo Finance
(`https://query1.finance.yahoo.com/v8/finance/chart/{CUR}USD=X`) — бесплатно, без ключа,
один запрос отдаёт весь диапазон дат по валюте.

Выбор источника сделан после проверки альтернатив: у `@fawazahmed0/currency-api`
история начинается примерно с марта 2024, а 35% дампа (2 325 строк, в основном ARS) —
раньше; Frankfurter (ECB) не покрывает RSD, ARS, PEN, RUB, AED, BAM; `exchangerate.host`
теперь требует ключ. Yahoo отдаёт всё нужное с 2023 года, кроме BAM и USDT — они
добираются через фиксированные привязки.

Алгоритм при импорте:
1. Собрать уникальные пары «валюта, диапазон дат», которых нет в `fx_rates`.
2. Запросить по одному ряду на валюту, записать в `fx_rates`.
3. Курс на дату операции, а если торгов не было — перенос последнего закрытия
   в пределах 4 дней (обычная практика для выходных и праздников), статус `ok`.
4. Дальше по времени или через привязку — статус `approx`.
5. Если API недоступен — импорт **не падает**: транзакции пишутся с `amount_base = NULL`
   и `fx_status = 'pending'`.

Валюты с фиксированной привязкой: BAM (валютный комитет Боснии, 1 EUR = 1.95583 BAM)
и USDT (стейблкоин к доллару). Выведенные так курсы помечаются `approx`.

Транзакции со статусом `pending` исключаются из денежных агрегатов, а API возвращает
`pending_count`, чтобы фронт показал баннер «курсы не загружены для N операций».
Добить курсы можно ручкой `POST /api/fx/backfill`.

Исторические курсы обязательны: ARS за 2023–2026 обесценился в разы, пересчёт старых
месяцев по текущему курсу дал бы бессмысленные цифры.

## Импорт CSV

Формат Дзен-мани: разделитель `;`, кодировка UTF-8 с BOM, заголовки
`date;categoryName;payee;comment;outcomeAccountName;outcome;outcomeCurrencyShortTitle;incomeAccountName;income;incomeCurrencyShortTitle;createdDate;changedDate;qrCode`.

Правила разбора:
- `outcome > 0`, `income == 0` → расход, берётся `outcomeAccountName` / `outcomeCurrencyShortTitle`.
- `outcome == 0`, `income > 0` → доход, берётся income-колонки.
- обе больше нуля → перевод между счетами, строка пропускается (в текущем дампе таких нет,
  но формат допускает).
- обе равны нулю → строка пропускается как ошибочная, попадает в `errors`.

Дедупликация по `zen_created_at`. Существующие строки не перезаписываются: возвращается
счётчик `rows_duplicate`. Транзакции с `source = 'manual'` импорт не трогает.

Импорт транзакционный: батч пишется целиком, ошибки парсинга отдельных строк
накапливаются и возвращаются в отчёте.

## Расчёты

Все агрегаты считаются в Python над выборкой транзакций месяца — объём данных
(~7 тыс. строк за 3.5 года, ~150 в месяц) этого не замечает, зато логика становится
чистыми функциями и покрывается юнит-тестами без БД.

- **Доход месяца** = `monthly_income.amount` (или `default_monthly_income`, если записи нет)
  + сумма income-транзакций месяца.
- **Траты месяца** = сумма outcome-транзакций месяца, кроме исключённых категорий и `pending`.
- **Сальдо** = доход − траты.
- **Доля израсходованного** = траты / доход.
- **Дельта категории** = (текущий месяц − предыдущий) / предыдущий; при нулевом предыдущем
  значении дельта не показывается.

## API

Все ручки под `/api`, требуют заголовок `Authorization: tma <initData>`.

| метод | путь | назначение |
|---|---|---|
| GET | `/api/meta/months` | месяцы с данными + текущий |
| GET | `/api/stats/month?month=YYYY-MM` | сальдо, доход, траты, топ категорий, последние операции, `pending_count` |
| GET | `/api/stats/categories?month=` | полная разбивка по категориям с долями и дельтами |
| GET | `/api/stats/category-dynamics?category=&months=12` | ряд по месяцам, среднее, тренд |
| GET | `/api/stats/compare?a=YYYY-MM&b=YYYY-MM` | сравнение двух месяцев по категориям |
| GET | `/api/transactions` | список с фильтрами `month`, `categories[]`, `q`, `accounts[]`, пагинация |
| POST | `/api/transactions` | ручное добавление |
| PATCH/DELETE | `/api/transactions/{id}` | правка/удаление (только `source = manual`) |
| GET | `/api/categories?month=` | список категорий для фильтров |
| GET/PUT | `/api/income/{month}` | доход месяца |
| GET/PUT | `/api/settings` | базовая валюта, доход по умолчанию |
| GET/PUT | `/api/plans/{month}` | план месяца со строками |
| GET | `/api/plans/{month}/vs-fact` | план против факта |
| POST | `/api/import/csv` | загрузка файла (multipart) |
| POST | `/api/fx/backfill` | догрузка недостающих курсов |

## Авторизация

Проверка подписи Telegram `initData`: HMAC-SHA256, секрет `HMAC_SHA256("WebAppData", bot_token)`,
проверка `hash` и свежести `auth_date` (окно 24 часа). `telegram_id` должен входить
в `ALLOWED_TELEGRAM_IDS`.

Бот ходит в API с внутренним заголовком `X-Internal-Token` (общий секрет из env),
чтобы не подделывать initData на сервере.

Для отладки в обычном браузере — `DEV_BYPASS_AUTH=true` + `DEV_TELEGRAM_ID`. Флаг работает,
только когда `ENV != production`.

## Бот

aiogram 3, long polling.

- `/start` — приветствие и кнопка открытия Mini App.
- Документ `.csv` — скачивание, отправка в `/api/import/csv`, ответ:
  «Загружено: N новых, M дублей, K ошибок» + кнопка открыть аппу.
- Планировщик (`apscheduler`): в предпоследний день месяца — напоминание выгрузить CSV
  и расписать план на следующий месяц.

Ошибки импорта не роняют бота: пользователю уходит понятное сообщение.

| маршрут | мокап | содержимое |
|---|---|---|
| `/` | 2b | переключатель трёх последних месяцев, сальдо крупно, донат трат, топ категорий с дельтами, последние операции, кнопка «Добавить трату» |
| `/transactions` | 2d | список по дням с фильтрами по категориям, счетам и поиском |

| `/compare` | 2h | сравнение двух месяцев |

Токены дизайна (цвета, нулевые радиусы, шкала отступов) переносятся из мокапа
в `globals.css` как CSS-переменные.

Шрифт: в мокапе Archivo, но у неё нет кириллического набора, а интерфейс русский.
Archivo остаётся для цифр и латиницы — на них держится вся типографика сумм, —
а кириллица падает на Inter, тот же нейтральный гротеск с начертанием 800.
Оба подключаются через `next/font/google` с `display: swap`, внешних CDN в рантайме нет.

Цвета категорий назначаются детерминированно: хеш имени категории → индекс в палитре
акцентных и нейтральных оттенков, чтобы цвет категории не прыгал между экранами.

Интеграция с Telegram: `window.Telegram.WebApp` — `ready()`, `expand()`, `BackButton`
для вложенных экранов, `MainButton` в формах, `HapticFeedback` на действиях.
Приложение работает и вне Telegram (для отладки), деградируя до обычной веб-страницы.

## Обработка ошибок

- Сеть недоступна / API вернул 5xx → экран показывает состояние ошибки с кнопкой «Повторить».
- Пустой месяц → пустое состояние с предложением загрузить CSV через бота.
- Курсы не загружены → баннер с числом операций и кнопкой «Загрузить курсы».
- Валидация форм на клиенте и сервере; сервер — источник истины.

## Тестирование

**Бэкенд** (pytest):
- парсер CSV: расходы, доходы, переводы, битые строки, BOM, дробные суммы;
- дедупликация: повторный импорт того же файла даёт 0 новых;
- конвертация валют: точное совпадение даты, ближайшая дата, отсутствие курса;
- агрегации: сальдо, разбивка по категориям, дельты, исключение `Correction` и `pending`;
- валидация initData: корректная подпись, испорченная подпись, протухший `auth_date`,
  чужой telegram_id;
- API-тесты через `TestClient` на SQLite.

**Фронтенд** (Vitest): форматирование сумм и дат, вычисление геометрии доната,
детерминированные цвета категорий, склейка транзакций по дням.

**Интеграционная проверка**: реальный дамп заливается в поднятый Postgres,
проверяется число строк и нулевой прирост при повторной заливке.

**Визуальная проверка**: каждый экран открывается в браузере на реальных данных
и сверяется с мокапом.

## Что вне объёма

- Мультивалютные счета и остатки по счетам.
- Переводы между счетами.
- Категоризация правилами или ML.
- Многопользовательский режим, роли, приглашения.
- Экспорт обратно в Дзен-мани.
