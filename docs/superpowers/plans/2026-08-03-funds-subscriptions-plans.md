# Средства, подписки и связка планов с фактом — план реализации

**Цель:** восемь доработок поверх готового приложения:

1. Учёт текущих средств: источники денег, история изменений, итог в долларах, график.
2. Ежемесячная сверка: реальное сальдо по счетам против учтённого, история погрешности.
3. Учёт подписок с автоначислением в последний день месяца.
4. Связка строк плана с категориями и сравнение по категориям.
5. Черновик плана следующего месяца из плана прошлого.
6. Перенос зарплаты на следующие месяцы.
7. Валюта строки плана (USD/EUR), итоги в базовой валюте.
8. Аренда квартиры как постоянная трата — тем же механизмом, что подписки.

**Ограничения:** те же, что в основном плане (см. `2026-08-02-finance-mini-app.md`).
Базовая валюта USD, деньги — `Decimal`, язык интерфейса русский, тесты обязательны.

---

## Решения

**Аренда — это подписка.** Пункты 3 и 8 просят одно и то же: сумма, периодичность,
автоначисление в последний день месяца, правка действует на текущий и будущие месяцы.
Отдельная сущность «аренда» дала бы вторую копию генератора начислений, поэтому обе
живут в таблице `recurring_expenses` с полем `kind` (`subscription` / `rent`).
«Правка действует вперёд» получается сама собой: месяцы, за которые начисление уже
создано, не пересчитываются, а будущие возьмут новую сумму.

**Начисления генерируются лениво.** Планировщик в боте — не единственный путь: если бот
не работал, месяц остался бы без подписок. Поэтому генератор идемпотентен
(`UNIQUE (recurring_id, month)`) и вызывается при чтении сводки месяца, плана и списка
подписок, а планировщик и ручка `POST /api/recurring/run` — дополнительные триггеры.
Начисляем только за завершившиеся месяцы, начиная с месяца создания подписки: иначе
новая подписка задним числом переписала бы историю трат.

**Реальное сальдо считается из снимков баланса.** Пользователь и так обновляет суммы
источников, отдельный ввод «реальных изменений» был бы тем же числом дважды. Реальное
сальдо месяца = итог на конец месяца − итог на конец предыдущего. Погрешность ввода =
реальное сальдо − учтённое (доход минус траты). Значение фиксируется в `month_checks`,
чтобы позднее обновление балансов не переписывало уже подтверждённую сверку.

**Курс для плана и балансов берётся на дату.** Строка плана в евро пересчитывается по
курсу на последний день месяца плана, но не позже сегодняшнего дня: план на будущее
считается по текущему курсу, прошлый месяц — по своему.

## Часть A — Бэкенд (`../finance_helper_back`)

### A1. Модели и миграция

**Файлы:** `app/models/__init__.py`, `app/models/enums.py`, новая ревизия Alembic.

Новое:

- `FundSource` — `id, user_id, title, currency, position, archived, created_at`.
- `FundBalance` — снимок: `id, user_id, source_id, date, amount_original, currency,
  amount_base, fx_rate, fx_status, note, created_at`. История — все строки, текущий
  баланс — последняя по `(date, id)`.
- `MonthCheck` — `id, user_id, month, real_saldo, tracked_saldo, discrepancy,
  note, created_at`, `UNIQUE (user_id, month)`.
- `RecurringExpense` — `id, user_id, kind, title, amount, currency, period_months,
  charge_day, category_name, active, starts_on, created_at`.
- `PlanLine` получает `category_name: str | None` и `currency: str` (по умолчанию `USD`).
- `Transaction` получает `recurring_id`, `recurring_month`,
  `UNIQUE (recurring_id, recurring_month)`; `TxSource` — значение `recurring`.

### A2. Сервис средств `app/services/funds.py`

**Производит:**

- `list_sources(db, user)` → источники с текущим балансом и суммой в базовой валюте.
- `set_balance(db, user, source, amount, date, note)` → новый снимок + пересчёт FX.
- `total_base(db, user, on: date)` → итог по последним снимкам на дату.
- `balance_history(db, user, months)` → точки «конец месяца → итог в базовой валюте».
- `month_check(db, user, month)` → расчёт сверки: реальное сальдо, учтённое, разница.
- `save_check(db, user, month, note)` → фиксация `MonthCheck`.

- [ ] Тесты: итог по разным валютам, история по месяцам, расчёт погрешности

### A3. Сервис регулярных трат `app/services/recurring.py`

**Производит:**

- `monthly_amount(item)` → `amount / period_months`, округление до 2 знаков.
- `due_months(item, until)` → завершившиеся месяцы от `starts_on` до `until`.
- `run(db, user, until)` → создаёт недостающие транзакции последним днём месяца,
  категория — из подписки, `source = recurring`; возвращает число созданных.

- [ ] Тесты: годовая подписка делится на 12, повторный запуск не дублирует,
      текущий месяц не начисляется, месяцы до `starts_on` пропускаются

### A4. Планы: категории, валюты, черновик

**Файлы:** `app/services/budget.py`, `app/api/budget.py`, `app/schemas.py`.

- `save_plan` принимает `(title, amount, currency, category_name)`.
- `plan_total_base` пересчитывает строки в базовую валюту через `FxService`.
- `GET /api/plans/{month}` при отсутствии плана отдаёт строки прошлого месяца
  с `source = "previous"`; сохранённый план — `source = "saved"`; иначе `"empty"`.
- `GET /api/plans/{month}/vs-fact` добавляет `lines[].fact` и `lines[].diff`
  по связанной категории и `unplanned` — факт по категориям вне плана.

- [ ] Тесты: пересчёт евро в доллары, черновик из прошлого месяца, факт по строке

### A5. Зарплата вперёд

`budget.get_income` при отсутствии записи на месяц берёт последнюю запись с `month <
target` (и только потом `default_monthly_income`). Правка месяца автоматически
распространяется на будущие месяцы без своей записи.

### A6. Ручки

```
GET    /api/funds                     источники, текущий итог, история
POST   /api/funds                     создать источник
PATCH  /api/funds/{id}                переименовать/архивировать
PUT    /api/funds/{id}/balance        новый снимок суммы
GET    /api/funds/{id}/history        история одного источника
GET    /api/funds/checks              история сверок
GET    /api/funds/checks/{month}      расчёт сверки месяца
POST   /api/funds/checks/{month}      зафиксировать сверку
GET    /api/recurring                 подписки и аренда, месячная сумма
POST   /api/recurring                 создать
PATCH  /api/recurring/{id}            изменить
DELETE /api/recurring/{id}            удалить
POST   /api/recurring/run             начислить пропущенные месяцы
```

## Часть B — Фронтенд

### B1. Клиент и навигация

- `lib/api.ts`: типы `FundSource`, `FundsOverview`, `MonthCheck`, `Recurring`,
  расширенные `PlanLine`, `Plan`, `PlanVsFact`.
- `TabBar`: пятая вкладка «Средства».
- `PlanTabs`: третья вкладка «Подписки».

### B2. Экран «Средства» (`/funds`, `/funds/check`)

Итог в долларах крупно, график общего баланса по месяцам, список источников с
инлайновой правкой суммы. Вторая вкладка — сверка: результат месяца, кнопка
«Сверить», история погрешности.

### B3. Экран «Подписки» (`/plan/recurring`)

Список подписок с месячной долей, форма добавления (название, сумма, валюта,
периодичность, день списания, категория), блок аренды, итог «в месяц».

### B4. План

Строка плана: название, категория (список категорий), валюта, сумма. Плашка
«черновик из прошлого месяца». План vs факт: колонка факта по категории строки.
